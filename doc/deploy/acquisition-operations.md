## ACQ-OP — operation catalog

| ID | Domain and operation | Evidence / limitations |
| --- | --- | --- |
| OP01 | Existing rsudo direct read or exec inject with fixed reviewed source: instance identity, selected process/service status, executable version, configured listeners, approved config paths | No unrestricted process arguments/env dump, no broad filesystem scan; read-only service queries only if available; avoid collecting secrets from command lines |
| OP02 | APISIX: rsudo apisix rest GET relative-resource, no body; list routes, services, upstreams, consumers/groups, plugin configs, global rules, relevant SSL/stream routes and plugin metadata where supported | Verify installed mode/API, version, HTTP success, body format, pagination and resource IDs; all applicable categories must be covered or explicitly unsupported; never log body/headers; no discovery via POST |
| OP03 | APISIX: targeted read of approved config files via fs get or fixed remote read; classify global settings, enabled plugins, admin endpoint and dependencies | Never blindly export etcd/database or private keys; secret-bearing configs restricted; prefer existing authorized read-only key, do not print key operation result or automatically obtain admin key |
| OP04 | Keycloak: rsudo keycloak kcadm get <resource> -r <realm> with nonsecret filters/pagination, version-supported endpoint discovery | Realm, client config, role definitions, role mappings, authorization resource/scope/policy/permission, federation settings (nonsecret subset), group hierarchy and in-scope associations; record client UUID vs clientId and role origin. Do not retrieve credentials, tokens, secret endpoints or full unrelated user directory. No direct AD operations. |
| OP05 | nginx: read known root config/includes, binary version, listener and service facts, path/permission metadata; effective-config inspection only if supported and confirmed side-effect-free for installed version | Resolve include graphs and symlinks within approved scope. Do not assume nginx -T is harmless (config test may open files/logs); no test/reload unless separately authorized. Compare actual listener/origin restrictions; inability to observe firewall means unknown, not secure. |
| OP06 | Cloaker/menu: approved candidate targets only, targeted hosting path/metadata and needed source inspection | Identify iframe/menu links and route associations; no crawls of other apps or scanning subnets. Unknown host stays unresolved if bounded inspection fails. |
| OP07 | Git/content: local Git rev-parse/ls-tree and approved private bare Git ref observation (git ls-remote or read via rsudo on existing host); targeted content fingerprints and metadata at deployed paths | Record exact object/ref and relative path; no clone/fetch modifying working trees, checkout, build or publish. Hashes of sensitive values excluded. Bare repository authority per D03; dirty working tree not equivalent. |
| OP08 | TLS: public certificate metadata (subject/SAN, validity, issuer, fingerprint), approved HTTPS endpoint handshake using existing trusted client; read certificate files only if confirmed public certificate not key | No key extraction, no insecure TLS bypass, no new cert generation. Public probes may generate normal access logs; no authenticated functional testing in acquisition unless separately approved. |
| OP09 | Network evidence: targeted listener, route and existing firewall-rule observations when permitted; approved single-endpoint reachability from intended locations | Config observation alone does not prove absence of alternate access. No port sweep, rule change, or unapproved probing. |

APISIX adapter includes HTTP headers (curl --include --fail). Parser must handle final HTTP status, multiple header blocks where present, body JSON and nonzero exit separately; reject ambiguous responses. API pagination is version-dependent: only use verified scheme; reconcile totals/unique IDs and detect repeated pages, truncation or concurrent change. No secret query strings.

Keycloak adapter sends remote source through stdin, then invokes kcadm with stdin closed; local file operands are remote paths. Existing session and actual CLI cache/refresh behavior must be established before using kcadm. No password/token via args, no blanket login, no export requiring service stop. Dispatcher logs module argv in debug: use only nonsecret args. Existing optional KC_CLI_PASSWORD handling is not permission to use it. If auth requires unapproved effects, mark blocked.

fs get writes locally, may stage/promote/replace, and preserves symlinks: select unique restricted destinations, verify resolved scope/links and reject traversal. Prefer targeted reads over full trees; no dereference into unapproved locations. exec inject consumes stdin as shell source; use fixed reviewed local source, never interpolate untrusted configuration as code. No automatic protected module changes.

## Sequencing
OP01 and authorized access check precede domain reads. OP02/03 and OP04 establish gateway/identity references; OP05/06/07/08/09 establish hosting/source/endpoint relationships, independent where safe. Collect both global and app scope; reconcile at coverage review. Stop dependent steps on missing prerequisites, continue unrelated permitted domains only within approved limits.
